# BusVision 雙手機外測

iPhone 16e、Galaxy S22 Ultra 及 Mac 開啟自動日期時間。兩台手機都在「外測工具」選擇「開始場次並開啟相機」。預設只記事件，可另外選擇儲存燈牌照片及進入畫面的無聲短片。回到場次可結束、查看最近一百筆、匯出完整 ZIP 或刪除。中斷的場次會保留已寫入事件。

Mac 在專案目錄執行下列命令。Xcode 需支援 devicectl，Android 需有 platform-tools。兩台均須解鎖並信任或授權這台 Mac。

```sh
python3 scripts/field/record.py --check
python3 scripts/field/record.py
```

iOS 會讀取手機場次，每一百筆換檔，重連時依序號補讀。裝置行程變動會留下 PID 與新增的系統診斷報告檔名，供比對退出時間。App 行程不在、USB 連線中斷或有 Jetsam 報告，都需要結合事故時間及報告內的目標行程判讀。Android 分開檢查 USB 授權、目前使用者是否安裝辨識器、logcat 是否收到辨識器事件。斷線期間仍可從 Android 手機匯出完整場次。每台的狀態保留 Mac 最後收到事件的時間。

## 雙機驗收

| 情境 | 操作及觀察 |
|---|---|
| 921 同名對向站 | 在臺北大學正門分別確認下一站。往三峽為學勤路，往景安為大學學成路口。兩台讀到單獨車號時都應說方向待確認。 |
| 同站多線與支線 | 改選第二條路線及一條支線，對照官方站序、目的地、下一站與實體站牌。紀錄站位、分支和不符之處。 |
| 進站事件 | 確認站位後使用一般辨識。同一車體先讀到 94、41，只有同側、近期進站且片段能唯一識別 941 才可輔助報號。三分鐘預估、過期、對街、單一數字或重疊車體繼續掃描。 |
| 動態 | 兩機並排對同一班車。操作員在車體進入共同視野時輸入實際路線與方向，例如 `941 三峽`。車離開時輸入 `end`。若當下無法確定車號，可先用 `note` 記錄，避免將晚認出車號的時間當作進入視野時間。 |
| 斷線與恢復 | 拔除一台手機、持續掃描、重新接線。比對手機事件序號與 Mac 時間。確認 iPhone 行程及場次接續。 |
| 無障礙 | 分別開啟 VoiceOver、TalkBack，操作站位選擇、開始與結束場次、查看、匯出及刪除一場測試資料。記下實際聽見的報號。 |

`status` 查看狀態，`note 兩車重疊` 可補記現場情境，`q` 結束。可用 `--platform ios` 或 `--platform android`，多台同平台裝置可指定 `--udid` 或 `--serial`。場次在 `test-results/field/`。使用 `python3 scripts/field/record.py --report 場次路徑` 重建報告。

逐車報告含首次正確確認、首次正確報號請求、未收到確認及其他車號。手機時間用於補讀事件定位，請在現場用備註記錄真正出聲與否。11 月 24 日基準僅 iPhone 有辨識資料，當時無人工車次標記。

[921 往景安](https://ebus.gov.taipei/EBus/VsSimpleMap?gb=0&routeid=0400092100) · [921 往三峽](https://ebus.gov.taipei/EBus/VsSimpleMap?gb=1&routeid=0400092100)
